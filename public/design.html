NPL Live Score – Design Guide

Colours, type, components and rules used on the site. ← Back to the live site

1. Colour

Follows the device's light or dark setting, and the ◐ button overrides it. Status colours carry a meaning, so each is always paired with a text label, never used alone. Team colours are generated from team names, so they are not listed here.

4. Layout and behaviour rules

  • Mobile first. One column, max width 820 px, 16 px side margins, no sideways scrolling.
  • Live first. The default tab is Live; if nothing is live, the page says so and points to Fixtures.
  • Always labelled. LIVE, RESULT and UPCOMING appear as words as well as colours.
  • Pulsing dot marks live matches. It is the only animation.
  • Auto refresh every 30 seconds and when the tab becomes visible again.
  • Language toggle (EN / नेपाली) is remembered on the device.
  • Theme toggle (◐ button) switches light and dark. With no choice made, it follows the device setting. The choice is remembered.
  • Team colours. Each team gets a stable colour made from its name. It colours the round logo and the stripe on the left of every match card. A real logo replaces the coloured circle when a picture named after the team's short code (for example logos/bir.png) is in the logos folder; teams without one keep the coloured circle with three letters. The data source's own icon is ignored, because it is the same generic picture for every team.
  • Match details. Tapping a match opens its scorecard at #/match/ID: result header, venue, toss, an innings switch, then batting and bowling tables. The Back button returns to the list. Upcoming matches have no scorecard yet.
  • Loading. Grey placeholder cards show while data loads, so the page never looks empty or broken.
  • Tables on phones. Scorecard tables fit a 360 px screen without sideways scrolling.
  • Reduced motion. Animations are switched off for people who ask their device for less motion.
  • Honest data. Sample data and a data-source outage are both announced in a banner on top.

5. Files

  • index.html – the live site (layout, styles and script in one file).
  • design.html – this guide.
  • server.js – optional backend that provides real scores at /api/matches.
